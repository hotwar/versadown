# 百度网盘登录与操作验收

## 登录可以维持多久

百度账号帮助说明，同一浏览器勾选自动登录并保留浏览数据，可以在下次使用时沿用账号。网盘帮助说明，删除操作有时需要本人验证。查询于 2026 年 11 月 20 日，所查官方资料均没有给出个人网盘网页或桌面客户端固定多少天退出，也没有保证仅主动退出才会结束会话。改密、清除本机数据和服务方的安全决定会影响能否继续使用。一次运行仅能证明那段时间内账号有效。[百度账号自动登录](https://help.baidu.com/question?class=9&id=2126&prod_id=28) · [异常登录验证](https://help.baidu.com/question2?class=9&id=2106&prod_id=28) · [百度网盘帮助](https://wangpan.baidu.com/disk/help)

开放平台提供另一种接入方式。用户批准应用权限后，服务返回访问令牌、刷新令牌、授权范围和有效时间。接入方按返回的 `expires_in` 维护访问令牌，刷新成功后一起保存新令牌。百度通用 OAuth 文档标注刷新令牌有效期十年。网盘开放平台还对上传目标和企业分享设有条件。决定迁移之前，需要用 VD 实际获批的应用验证目标目录和分享能力。[百度 OAuth 接入指南](https://openauth.baidu.com/doc/doc.html) · [网盘官方 SDK](https://github.com/baidu-netdisk/baidu-drive-sdk-go) · [上传路径](https://help.baidu.com/question?class=0&id=1002129&prod_id=257) · [分享条件](https://help.baidu.com/question?class=0&id=1002133&prod_id=257)

VD 当前使用用户在本地授权的百度会话。桌面为该用户保存网盘授权和官方授权窗口的浏览数据。此实现没有开放平台的刷新令牌，也没有自行给百度登录设定退出日期。不同便携 Quick 的数据目录可能独立，换版本测试时应记录所用配置目录。

## 原生上传的外部条件

百度开放平台提供正式上传接口。官方 SDK 演示了在应用目录内预创建、按需上传分片、提交文件并下载校验。百度对标准分片接口列出应用目录限制。百度自己的 MCP 工具也提供目标路径参数。具体接入身份和授权决定目标范围，SDK 参数本身无法证明某个应用可以写入用户根目录。[百度官方 SDK](https://github.com/baidu-netdisk/baidu-drive-sdk-go) · [官方真实账号测试源码](https://github.com/baidu-netdisk/baidu-drive-sdk-go/blob/main/baidudriver/scene/integration_test.go) · [上传目录 FAQ](https://help.baidu.com/question?class=0&id=1002125&prod_id=257) · [百度官方 MCP](https://github.com/baidu-netdisk/mcp#使用准备)

同行项目有两种可对照的实现。OpenList 通过开放平台 OAuth 维护账号授权，由驱动接收用户选择的目录并上传。BaiduPCS-Go 的维护分支提供客户端内上传到指定网盘目录，使用个人登录会话及 PCS 上传流程。这些是各项目的实现依据。VD 能否用自己的登录会话完成上传，还要在 VD 实际的目标目录验收。[OpenList 百度驱动](https://doc.oplist.org/guide/drivers/baidu) · [BaiduPCS-Go 上传说明](https://github.com/qjfoidnh/BaiduPCS-Go/blob/1b9131817aaf8ca7dee24bc00e33ebc4c7a5cc73/README.md#L616-L636)

VD 项目没有登记百度开放平台应用。本轮沿用 VD 已有的本地账号授权和原生上传。用户在 VD 中选择文件和目标目录；需要本人确认登录时，由 VD 打开已有的账号授权窗口。

## 操作与会话

| 操作 | VD 需要验证什么 | 失败后怎么处理 |
| --- | --- | --- |
| 登录、启动或恢复 | 账号身份与本地授权是否相符 | 复用同账号已有会话。已主动退出时保留退出状态。真正需要本人验证时交回官方页面 |
| 根目录、任意层子目录、翻页、容量、回收站和自己的分享记录 | 账号和相应读取接口 | 读取遇到疑似会话拒绝时，在同一 HTTP 会话核实账号，最多重新发一次该读取。网络错误、单项拒绝与官方操作验证分别呈现 |
| 上传 | 本地文件可读、目标目录可用、写令牌、预创建、所需分片、最终提交 | 写前可恢复。服务端可能已提交时先检查目标，避免从头重传同一写入 |
| 新建、改名、移动、复制、移入回收站、恢复和永久删除 | 当前账号、源项目和目标位置，以及百度对这次写入的许可 | 单次写入。极敏感操作由百度决定是否要求本人验证。验证后重新核对目标 |
| 个人盘下载 | 文件身份、所在目录、下载地址及实际返回的数据 | 定向测试校验下载内容；地址失效、源文件消失、权限不足各自处理 |
| 对盘内项目创建分享、查看自己的分享、撤销分享 | 当前账号对项目的权限、提取码策略、分享 ID | 创建或撤销后从分享列表核对。接收别人分享时的提取码是另一项输入 |
| 并发、退出与切换账号 | 账号绑定与会话版本 | 迟到的目录或账号结果不得覆盖新导航、退出或新账号；同一账号的并发恢复复用已验证结果 |

## 验证方式

直接在 VD 的生产适配器上验证。确定性测试注入分页中途失效、网络中断、两次拒绝、用户取消、乱序返回和写入结果未知。真人账号验收则发现模拟响应无法覆盖的百度策略与返回格式。独立模拟客户端还需要重新实现会话存储和桌面调用顺序，本次选用同一套实现做两层测试。

Windows 适配器验收于 2026 年 11 月 20 日执行。使用常规桌面配置中的已授权账号，全新 HTTP 客户端直接向本次新建的子目录上传合成文件，跨客户端读取并逐字节校验下载。容量、目录、改名、复制、移动、创建一天有效的带码分享、列出与撤销、移入回收站和恢复成功。永久删除返回了操作验证要求，目录留在回收站，分享已撤销。本次未进行跨天失效观察或跨账号分享转存。

同日，用户在 Windows Quick `e9df4f1` 中向百度网盘根目录上传一个安装程序失败，并确认百度网页版可以把同一文件上传到同一目录。使用该 Quick 保存的账号复测桌面上传后端，读取账号和根目录成功，取得上传令牌后，百度在预创建阶段返回 HTTP 200、errno -6。测试使用 1,048,592 字节的独立合成文件，未进入分片或提交。该 Quick 的原生上传验收失败。常规配置的适配器测试保留为单独结果。

进一步对照确认，两份配置对应同一百度账号。使用同一桌面上传后端、同一根目录及等长的新测试文件，Quick 中标记为 `Password` 的会话返回预创建 `-6`；常规配置中标记为 `Web` 的会话成功预创建和提交，目录返回了对应文件 ID。经稍后复查，测试文件已进入回收站。首次回收查询尚未更新，致使该轮测试没有单独报告下载字节断言。登录方式是 VD 保存的来源标签，无法单凭标签确定服务方的拒绝原因。

复测桌面上传时，显式选择正在验收的 Quick 的 `cloud-sessions` 目录，并设置 `VERSADOWN_LIVE_BAIDU_FIXTURE=1`。在 Windows 上使用该实例实际使用的规范路径。设置 `VERSADOWN_BAIDU_DIAGNOSTIC=1` 后，可查看上传阶段、HTTP 状态和百度错误码。

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib desktop_baidu_upload -- --ignored --nocapture
```

此测试通过桌面文件选择后的批处理入口上传唯一命名的合成文件。成功时核对网盘目录中的文件身份和下载字节，再将测试文件移入回收站。人工验收还需通过实际桌面窗口选择文件并核对目标目录。只有原生上传完成并核对文件，才记录该配置的原生上传通过。

可重复的真实用例为 `src-tauri/tests/live_baidu_session.rs`。显式设置 `VERSADOWN_LIVE_BAIDU_FIXTURE=1`，将 `VERSADOWN_LIVE_BAIDU_UPLOAD_PROBE_DIR` 指向用户选定的现有 `cloud-sessions` 目录，在配置好 Windows 工具链的终端执行：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --test live_baidu_session -- --ignored --nocapture
```

该用例会创建本次专用目录，生成自己的小文件、短期带码分享和回收站记录。每次运行都会产生新的测试数据。永久删除需要本人验证时记录该边界并停下。普通回归应保持真实用例为忽略状态。需要观察更长登录期限时，应固定同一设备和配置，在用户自然使用时记录最近一次成功、首次被拒绝的日期和是否需要本人操作；只有这段观测构成该账号的实测下限。
