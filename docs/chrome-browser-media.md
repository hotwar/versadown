# Chrome 开发者版「万能下载+」

在画面右上角点「万能下载+」，Chrome 将所点视频交给 VD。VD 在后台运行随包的 yt-dlp，插件在原画面下展示可以选择的画质。选一次即用 VD 默认下载目录创建任务。VD 可以从退出状态启动，解析时不弹出新建任务窗口。只有一档也会出现在菜单里。

## 安装到本机 Chrome

1. 准备支持浏览器选源协议 v3 的 VD。首次切换开发版时退出旧版 VD。macOS 独立开发包内的 yt-dlp 包括同目录的运行依赖。
2. 在产品源码目录，把该版本 VD 注册为当前用户的 Chrome Native Messaging 宿主。macOS 可传 `.app` 或其中的可执行文件。Windows、Linux 传可执行文件路径。应用换位置后重新注册。

   ```sh
   node scripts/register-chrome-host.mjs --app "/absolute/path/to/VersaDown.app"
   ```

3. 打开 `chrome://extensions` 并开启「开发者模式」。点击「加载已解压的扩展程序」，选择产品源码下的 `browser-extension`。扩展 ID 为 `koomjmkmehhhpkncngdkpkbfbjjbnccf`。已有同一扩展时，在该页重新加载，然后刷新播放页。
4. 默认在 B 站、YouTube、X、X 官方嵌入页及本地开发页检测。点击 Chrome 工具栏扩展图标，开启「检测所有视频」并授权后，扩展也在其他 HTTP(S) 网页及其可访问的播放器框架中检查 HTML 视频。授权后当前标签页会尝试立即加载。其他已开标签刷新后加载。关闭开关会移除其他站点上的按钮。

## 每个按钮解析它所在的画面

| 播放场景 | 交给 VD 的目标 |
| --- | --- |
| B 站 | 当前播放器对应的 BV/AV 地址及分 P。 |
| YouTube | 所点播放器的视频 ID。播放画质与下载列表可以不同。 |
| X 及官方嵌入页 | 可确认的附件专属链接。一个帖子含多段视频时，整帖网址不足以定位其中一段。 |
| 其他网页 | 单播放器时优先检查该框架页面。能明确绑定播放器的 HTTP(S) 文件或 HLS/DASH 清单可用于回退，也可在多播放器页面上独立解析。 |

扩展在用户点击按钮后才联系 VD。插件遇到只有 `blob:` 的多播放器页面又无法确认视频地址时，会提示无法定位。Chrome 管理页等不允许注入的位置、网页未暴露的播放器，以及站点访问限制也会影响识别。列表反映本次账号设置与网络条件下 yt-dlp 拿到的可选格式。源站仍可能在传输阶段拒绝特定地址。VD 使用自己的代理设置及用户配置的视频 Cookie 文件。

宿主名为 `com.versadown.browser`，注册时只允许上述扩展 ID。macOS 安装后，VD 选用随包 yt-dlp 的目录版，免去每次启动时释放内嵌依赖。旧版包的单文件查找路径仅用于兼容。

## 验证

```sh
node --test browser-extension/tests/*.test.mjs scripts/browser-site-media.test.mjs
```

验收时先退出 VD，点击画面按钮并检查原位选源。确认一种画质后关闭网页，使用下载任务与成品验证画质、时长及音画轨道。区分“列出了可选档”和“任务已完成”。

0.3.0 实测同一条 YouTube 视频 `62xlzGs8LXA`。从真实 Chrome 点击「万能下载+」，后台冷启动 VD，在原画面列出 144p、240p、360p、480p、720p、1080p、1440p、2160p。菜单出现时没有任务。选择 720p 并在收到确认后立即关闭网页，此时任务刚开始、完成字节为 0。最终得到 65,592,429 字节、17:00.08、1280×720 H.264 和 AAC。该次隔离实例使用测试机的 HTTPS 代理。从按钮点击到菜单出现约 32 秒，包含应用冷启动、网络和提取时间。已完成下载的档位为 720p。

同版在非默认站点的普通 HTTP 双播放器页面实测。开关关闭时页面没有按钮，开启并授权后两个画面均有按钮。点击其中一个画面只显示其自身的 MP4。选择后立即关页，VD 从 0 字节继续下载，最终得到与该源校验值一致的 640×360 H.264 和 AAC 文件。

## 旧版直接选源方案的记录

下面为 0.2.x 测试与 yt-dlp 命令行对照结果。0.2.x 在 Chrome 枚举媒体，选定一个地址后再启动 VD。

### 2026-11-18 的公开站点抽测

环境为 macOS Apple Silicon、Google Chrome 157 的临时未登录配置。在开发者模式加载扩展后点击 B 站和 YouTube 的页面按钮。0.2.0 首次点开两个站点的选源菜单时，实测本机宿主调用共零次。另对 B 站两个档位用随包 aria2-next 3.0.9 验证，对 X 核对官方嵌入数据并尝试独立请求。

| 样本 | 实际观测 |
| --- | --- |
| [B 站 BV1ps411o7yC](https://www.bilibili.com/video/BV1ps411o7yC/) | 0.2.1 原样打开带分享参数的普通播放页。菜单列出 360p、480p，各有 H.264、HEVC；播放器实际在用 360p HEVC。点选 480p H.264 后关闭网页，VD 下载完成，ffprobe 确认 852×480 H.264 与 AAC、85.193 秒、9,802,563 字节。该视频的官方嵌入播放器也能按视频元素和当前 CID 匹配四项。 |
| [B 站《Big Buck Bunny》](https://www.bilibili.com/video/BV1Zs411o7Ee/) | 当前播放为 640×360 的 `blob:`，扩展实际展示 480p H.264、360p H.264 两个选项。播放器额外报告了 720p，但未交付相应轨道地址。关闭 Chrome 后分别下载，ffprobe 检出 852×480 和 640×360 的 H.264 画面，两份都有 AAC 声音，容器时长均为 596.624 秒。在 0.2.0 的真实 Chrome 菜单点选 480p 后，VD 冷启动直接建任务；关闭网页时队列状态为 downloading，随后完成。该份文件为 63,940,586 字节，ffprobe 确认 852×480 H.264 和 AAC。 |
| [YouTube 的 Blender 官方视频](https://www.youtube.com/watch?v=YE7VzlLtp-4) | 播放器列出 33 条自适应格式，包含 144、240、360、480、720、1080p；本次所有记录均缺少可交付 URL，也没有 HLS/DASH 清单。实际观察到 UMP 播放响应。即使当时能够播放 480p，VD 仍没有可独立下载的档位。 |
| [X 的 NASA 发射视频](https://x.com/NASAKennedy/status/1798306406770319512) | 公开帖子和 NASA 媒体页在测试会话都返回 HTTP 403，未进入播放器。X 的媒体 ID、双播放器归属和清晰度提取已用固定响应测试，真实站点成功率仍待可正常播放的会话验证。 |
| [X 的 Ekimko 帖子（官方嵌入）](https://platform.twitter.com/embed/Tweet.html?id=2111347724071088497) | 官方嵌入数据的三个媒体对象各有独立的 HLS 清单和三条 MP4。未登录 Chrome 直访 x.com 原帖返回 HTTP 403。首次直连媒体 CDN 时连接被关闭；下方记录了 0.2.2 使用系统代理取得的成品。 |


同一轮用 VD 0.3.1 发布包自带的 yt-dlp 2026.10.26 单独做格式枚举。B 站样本返回 360p、480p、720p，协议均为 HTTPS。YouTube 样本返回六档，其中 11 条格式记录走 HLS，18 条走 HTTPS。X 的元数据请求遇到 TLS 错误。此对照只枚举格式，未用 yt-dlp 执行扩展任务。

差异来自资源发现方式。扩展可读播放器已经获得的媒体描述和清单；yt-dlp 的站点提取器还会主动以视频标识查询播放接口，再展开返回的 HLS 或 DASH。两条路径看到的响应可以不同。[B 站提取器](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/bilibili.py#L214-L233) · [YouTube 提取器](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/youtube/_video.py#L3684-L3731)

0.2.1 修正了 Chrome 单页导航后的地址校验。Chrome 157 在同一文档切换路由或更改时间标记后，传给扩展后台的发送者地址可能仍是首次打开的地址。扩展现以文档身份、当前同源播放页和所点画面绑定选项。实测同一标签页连续跳转后均可选源。

YouTube 的《Big Buck Bunny》与《Sintel》在本轮未登录 Chrome 中只给出 SABR 会话地址；实际播放使用 POST，响应为 `application/vnd.yt-ump`。两个样本均未取得可独立请求的完整文件、音视频轨道或 HLS/DASH 清单，当前版本无法下载这种会话。

### 0.2.2 的选源与网络验证

YouTube 视频 `62xlzGs8LXA` 在测试会话中实际播放 854×480，播放器报告的最高档位为 2160p；该次播放使用 SABR。另一次会话为同一视频创建了 360p H.264 直链任务（itag 18）。VD 的实际任务结果是连接超时，收到 0 字节。在地址仍有效时对同一条链接复测，直连无法建立连接，经 macOS 已配置的 HTTPS 代理收到 HTTP 403。点选 YouTube 的文件或分轨后，0.2.2 在 Chrome 中读取开头的媒体字节；配对轨道两者均须通过检查。测试原任务地址时，扩展返回 403，未调用 VD。这个检查反映 Chrome 当时的网络路径，VD 使用自己设置的下载代理。

公开 X 帖页面没有匹配到源时，0.2.2 提供打开该帖官方嵌入页的链接。在 Ekimko 帖子的官方嵌入页，真实 Chrome 显示三个附件各自的「万能下载」。所点画面的菜单列出 720×1280、480×852、320×568 和 HLS 自动选轨。点选 720×1280 前隔离的 VD 队列为空，确认后关闭网页时任务处于下载中，随后完成 16,405,256 字节。ffprobe 检出 H.264、AAC，时长 60.302 秒。该次隔离 VD 使用测试机已有的系统 HTTPS 代理。日常 VD 的设置未更改，未登录会话仍无法验证 x.com 原帖上的同一操作。

另用本开发包自带的 yt-dlp，经同一系统代理、未提供账号 Cookie，枚举上述三个用户样本。B 站 BV1ps411o7yC 返回 360p、480p、720p。X 的该视频附件专属链接返回三档 MP4。YouTube 62xlzGs8LXA 返回 38 条含视频的格式记录，覆盖 144p 到 2160p 共八档。对 YouTube 的 720p HTTPS 视频轨单次取样收到 403，同画质 HLS 清单可读。使用随包 yt-dlp 选取 720p H.264 的 HLS 画面与 M4A 音轨、启用分片重试，由随包 FFmpeg 合并，得到 65,783,623 字节的成品，时长 17:00.08、1280×720 H.264 和立体声 AAC。此项从本地命令行启动，浏览器按钮尚未接入 VD 的 yt-dlp 解析流程。
